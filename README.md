# Insn — interactive research map

A Flask application for exploring an interactive arXiv paper map, fetching paper details, asking abstract-based questions, and discovering related papers.

## Overview

This version of Insn uses Datamapplot example data to render the research landscape, arXiv for metadata lookup, Semantic Scholar for recommendations, and OpenAI for question answering. It is distinct from the FAISS-based `Insn` prototype.

## Features

- Landing page and research-exploration interface.
- Interactive map with search and click-to-open paper details.
- Paper metadata, abstract, author, DOI, and PDF links.
- Questions answered from paper metadata and abstracts.
- Latest `cs.CL` papers for the current UTC date.
- Paper and author suggestions based on saved/followed inputs.

## Architecture

`/plot` downloads coordinate, cluster-label, and hover-data arrays from the Datamapplot example repository and embeds an interactive plot. Clicks invoke the parent interface's paper-detail lookup. The Flask routes search arXiv by title, cache details in memory, and call external APIs for answers and recommendations.

The question-answering route provides metadata and the abstract to GPT-4; it does not read the full PDF. Requested inline citations are generated by the model and are not independently verified.

## Tech stack

Python, Flask/Jinja templates, NumPy, Datamapplot, arXiv client, Requests, Beautiful Soup, legacy OpenAI Python SDK, and Gunicorn.

## Project structure

- `app.py` — web routes, external API calls, plotting, and caches.
- `templates/landing.html` — landing page.
- `templates/index.html` — research interface.
- `requirements.txt` — Python dependencies.
- `Procfile` — Gunicorn entry point.

## Run locally

Create and activate a Python virtual environment, then:

```bash
git clone https://github.com/anishkganesh/Insn_.git
cd Insn_
python -m venv .venv
pip install -r requirements.txt
```

Set `OPENAI_API_KEY` in your shell for question answering. For example, in PowerShell:

```powershell
$env:OPENAI_API_KEY="your-openai-key"
python app.py
```

Open `http://localhost:5000`, then enter the application at `/app`. Do not expose Flask debug mode as a public production server.

## Configuration and data

The dependency file pins `openai==0.28`, matching the legacy `ChatCompletion` interface. The code requests `gpt-4-0613`; availability in your account must be checked and the model identifier may need adaptation for a future local run.

The map depends on remote `.npy` files from TutteInstitute/Datamapplot. Some arrays are loaded with `allow_pickle=True`, so they must be treated as trusted external inputs. Paper-detail and daily-result caches are in memory and disappear when the process restarts; multiple workers have separate caches.

## Usage

Open the map, search or click a paper, inspect its details, and ask a question about the abstract. Use recommendations as discovery suggestions rather than a trained personalization guarantee.

Routes include `/`, `/app`, `/plot`, `/get_arxiv_details`, `/ask_paper`, `/proxy`, `/latest_papers`, and `/get_recommendations`.

## Validation

No automated test suite is included. Check remote map loading, arXiv title matching, PDF links, question answering, recommendations, and empty latest-paper results. This documentation review did not run external requests or paid model calls.

## Deployment

The Procfile starts `gunicorn app:app`. Supply the API key and outbound network access on your host. Review worker memory and caching behavior. The unrestricted URL proxy requires access controls/URL validation before public hosting.

## Limitations

- The map is downloaded example data, not an embedding map computed by this app.
- Fuzzy title lookup can select an incorrect paper.
- Latest-paper filtering uses a small current-day category result set; the followed-author filter searches titles, and the daily cache is shared rather than keyed by user/filter.
- Recommendations use API searches and a random saved-paper query, not a learned recommender.
- The URL proxy and generated HTML responses need review before untrusted public use.
